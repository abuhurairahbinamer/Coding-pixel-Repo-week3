# P8 Task

##  Overview

This project demonstrates how to properly handle cleanup in React hooks
like: - setInterval - setTimeout - Event Listeners

------------------------------------------------------------------------

##  Why Cleanup is Important

In React, side effects continue running even after a component unmounts
unless explicitly cleaned up.

Without cleanup, you may face: - Memory leaks - Duplicate logs -
Multiple event triggers - React warnings

------------------------------------------------------------------------

## Cleanup Examples

###  setInterval

``` js
useEffect(() => {
  const id = setInterval(() => {
    console.log("Running...");
  }, 1000);

  return () => clearInterval(id);
}, []);
```

 Without cleanup: interval keeps running forever.

------------------------------------------------------------------------

###  setTimeout

``` js
useEffect(() => {
  const id = setTimeout(() => {
    console.log("Executed");
  }, 2000);

  return () => clearTimeout(id);
}, []);
```

 Without cleanup: may run after unmount.

------------------------------------------------------------------------

###  Event Listener

``` js
useEffect(() => {
  const handler = () => console.log("Clicked");

  window.addEventListener("click", handler);

  return () => window.removeEventListener("click", handler);
}, []);
```

 Without cleanup: multiple listeners stack up.

------------------------------------------------------------------------

##  Common Warning

"Can't update state on an unmounted component"

### Why it happens:

-   Async work (timeout, interval, API call) finishes after component
    unmounts
-   It tries to update state → React throws warning

------------------------------------------------------------------------

##  Key Rule

Always return a cleanup function in useEffect when using: - Timers -
Event listeners - Subscriptions

------------------------------------------------------------------------

##  One-Line Summary

Cleanup ensures side effects stop when the component unmounts,
preventing bugs and memory leaks.
