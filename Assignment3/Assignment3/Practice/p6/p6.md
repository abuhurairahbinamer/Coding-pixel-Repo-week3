# P6 task -- React.memo 

## 1. React.memo Bail-out Rule

React.memo prevents a component from re-rendering if its props are
shallowly equal (primitives are compared by value, objects by
reference).

------------------------------------------------------------------------

## 2. Does memo help with `id: string`?

Yes.

-   `id` is a primitive (string)
-   Compared by value
-   If the value does not change → no re-render

------------------------------------------------------------------------

## 3. What about `children`?

No (in most cases).

-   `children` is usually a React element (object)
-   A new object is created on every render
-   Reference changes → React.memo cannot skip re-render

------------------------------------------------------------------------

## 4. Why does this happen?

Even if JSX looks the same:

``` jsx
<p>Hello</p>
```

A new object is created each time, so:

    oldChildren !== newChildren

------------------------------------------------------------------------

## 5. CHECK Summary

-   `id` only → no re-render 
-   `children` → re-renders 

------------------------------------------------------------------------

## 6. How to stabilize children?

### Option 1: useMemo

``` jsx
const child = useMemo(() => <p>Hello</p>, []);
<Child>{child}</Child>
```

### Option 2: Move outside component

``` jsx
const staticChild = <p>Hello</p>;
<Child>{staticChild}</Child>
```

------------------------------------------------------------------------

## 7. Is it worth it?

Usually NO.

-   JSX creation is cheap
-   useMemo adds complexity
-   Can reduce readability

------------------------------------------------------------------------

## Final Summary

-   React.memo works well with primitives
-   Does not work well with objects like children
-   Children can be stabilized, but it's rarely necessary

------------------------------------------------------------------------

## One-line takeaway

React.memo compares references, and children usually get a new reference
on every render.
